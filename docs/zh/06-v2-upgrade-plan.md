## 二、调研结论（已实测验证，非推断）

### 2.1 引擎能力边界

当前运行实例为命令行模式（`runtime_recipe.id = @command-line`），`features` 与 `generation_features` 中与本次相关项全部为 true：

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| `init_image` | true | 底图（图生图 / 改图） |
| `mask_image` | true | 遮罩（局部重绘） |
| `ref_images` | true | 参考图数组（图参照生图） |
| `ip_adapter_image` / `control_image` | true | 本次不使用，留作后续 |
| `hires` / `vae_tiling` / `preview` | true | 高清修复、分块解码、预览 |
| 采样器 | 21 种（euler / res_multistep / er_sde 等） | 已由 v1.0 暴露 |
| 调度器 | 18 种（discrete / karras / beta / kl_optimal 等） | 已由 v1.0 暴露 |
| 尺寸限制 | 64~4096，`size_multiple=8`（Qwen 实际按 32 对齐） | 沿用 1.0 的 32 对齐 |
| 批量上限 | 8 | — |

`qwen-image-21` recipe 声明：`ref_images=true`、`img2img=true`、`mask_image=true`、`flow_shift=true`，`img_cfg=false`、`distilled_guidance=false`、`controlnet=false`。即 Qwen-Image 2.1 本体原生支持"参考图 + 底图/遮罩"三条腿，无需换用 qwen-image-edit 权重。

### 2.2 图片字段的准确格式（关键，决定了实现方式）

引擎请求体（`POST /sdcpp/v1/img_gen`）中图片一律为 **base64 dataURL 字符串**，不是本地路径：

| 字段 | 类型 | 格式 |
| --- | --- | --- |
| `init_image` | string \| null | `data:image/png;base64,...` |
| `mask_image` | string \| null | 同上，单通道语义 |
| `ref_images` | string[] | dataURL 数组 |
| `control_image` / `ip_adapter_image` / `end_image` | string \| null | 同上 |
| `auto_resize_ref_image` | bool | 参考图自动缩放到目标尺寸（建议 true） |
| `strength` | float | 去噪强度，仅 init 路线有效 |
| `increase_ref_index` / `ref_image_args` | bool / string | 参考图索引提示，暂不启用 |

传入本地路径或对象会直接返回 `400 invalid generation parameters`（已实测）。

### 2.3 两条改图通道实测结果

测试条件：Q3_K、1344×768、20 步、euler + discrete + flow_shift 3.0 + txt_cfg 1.6 + distilled_guidance 3.5，底图为已生成建筑图。

| 通道 | 请求 | 结果 | 掩码内平均差异 | 掩码外平均差异 | 耗时 |
| --- | --- | --- | --- | --- | --- |
| A 硬遮罩改图 | `init_image` + `mask_image`(中间矩形白) + `strength=1.0` | 成功，矩形区域明显重绘 | 61.0 | 1.48 | 267 s |
| B 参考图改图 | `ref_images=[底图]` | 成功，整图转为夜景 | 87.6 | 88.5 | 556 s |

由此确认三点结论：

1. **遮罩极性：白色 = 重绘区，黑色 = 保留区**（掩码内 61.0 对掩码外 1.48 已证）。
2. **掩码外并非绝对零差异**（1.48 源于 VAE 全图编解码）。因此 2.0 必须做 **CPU 侧合成复核**：把引擎输出与底图按遮罩二值化合成，掩码外像素强制还原为原图，引擎原始输出另存 `*_raw.png`。此为已知踩坑，直接内建。
3. **`ref_images` 与 `init_image`/`end_image` 互斥**（引擎前端逻辑明确报错）。所以"模板 + 遮罩"不能同时硬绑定到一条请求里，必须按模式分流（见 3.3）。

### 2.4 性能现实

- 硬遮罩改图约 267 s/张，参考图改图约 556 s/张（20 步、1344×768）。
- 慢的根因是文本/视觉编码跑在 CPU（`te=cpu,vae=cpu`，Qwen3VL-8B 编码 + CPU VAE 解码），不是采样本身。
- 影响：2.0 的轮询超时必须由 1.0 的 900 s 提到 **1800 s**，并给出"改图通常 3~10 分钟"的明确提示，避免用户误判卡死。

## 三、2.0 功能设计

### 3.1 总体结构（单文件、零依赖、双击即用，延续 1.0）

```
顶部：引擎连接条（端口自发现 / 状态 / 当前模型 / 当前 recipe）
├─ 模式切换：① 文生图  ② 图参照生图  ③ 局部改图
├─ 图像区（按模式显示）
│    ├─ 底图/参考图 载入：点选文件、拖拽、粘贴（Ctrl+V）、从上次结果载入
│    ├─ 遮罩画布（模式③，以及模式②的可选标注层）
│    └─ 预览缩略图条（多参考图时 1~3 张排序、删除、替换）
├─ 参数区
│    ├─ 量化档位 · 校准预设（Q3_K/Q4_K/Q6_K 三档，沿用 1.0）
│    ├─ 采样参数（步数/采样器/调度器/flow_shift/txt_cfg/distilled_guidance/eta/尺寸/种子）
│    ├─ 改图参数（strength、遮罩羽化、掩码外保护开关、参考图模式专属：auto_resize）
│    └─ 输出（批量数、格式、下载/图库/JSON）
└─ 运行日志 + 进度（引擎侧 queued/running/耗时，改图模式显示分阶段提示）
```

### 3.2 模式一：文生图

与 1.0 完全一致（含三档最佳参数）。仅做两点增强：支持"把上次结果作为底图/参考图接力"，以及结果一键送入改图模式。

### 3.3 模式二：图参照生图（ref_images 路线）

- 输入：1~3 张参考图（dataURL 数组，顺序即参考序号）。
- 参数：沿用最佳参数；`auto_resize_ref_image=true`。
- 语义：以参考图的构图/材质/风格为条件重新生成，适合"换风格、换光照、换材质、扩方案"。
- 与模式三的分流：**参考图路线不支持硬遮罩**，遮罩在此模式下降级为"标注层"——把选区以半透明色块 + 描边 + 序号烧录进参考图副本，再用自然语言指令让模型只改标注区（见 3.4.4）。

### 3.4 模式三：局部改图（init + mask 路线）与遮罩系统

#### 3.4.1 请求构造
`init_image` = 底图 dataURL；`mask_image` = 由画布导出的黑白 PNG（白=改，黑=留）；`strength` 可调（默认 0.85，1.0 为完整重绘）；其余采样参数沿用当前档位预设。

#### 3.4.2 绘制（画笔类工具）
| 工具 | 交互 |
| --- | --- |
| 画笔 | 自由涂抹，笔刷直径 4~200 px，硬度可调 |
| 橡皮 | 擦除遮罩 |
| 矩形 / 椭圆 | 拖拽成框，可叠加多个 |
| 套索 | 多边形自由圈选 |
| 全选 / 反选 / 清空 | 一键操作 |
| 缩放平移 | 画布支持滚轮缩放与空格拖拽（便于精细描边） |

#### 3.4.3 标识（可视化）
- 遮罩以半透明红（默认 45% 不透明度）+ 1px 描边实时叠加在底图上，与底图对比清晰但不遮挡判断。
- 实时显示：覆盖率百分比、连通区域数量、当前画布尺寸与引擎对齐状态（是否 32 整除）。
- 空遮罩点生成时直接阻断并提示，不发无效请求。
- 可选网格 / 三分线辅助，便于按建筑立面比例取区。

#### 3.4.4 识别（三种候选，需你定选择性——见第五节决策点 1）
- **方案 A：遮罩自检识别（纯本地几何，推荐必做）**
  统计覆盖率、连通域数量、最大区域外接框、边缘贴边检测；对"过小区域（<0.2%，模型基本无响应）""过大区域（>85%，等于整图重绘，建议改用模式二）"给出提示。
- **方案 B：选区内容识别（选区主色 / 亮度统计）**
  对选区做像素统计，输出主色调、平均亮度、对比度，并自动生成可插入提示词的中文描述（如"该区域当前为深灰混凝土、平均亮度 0.31"），减少反复试错。纯前端 canvas 采样，零额外算力。
- **方案 C：候选选区建议（边缘密度分析）**
  对底图做 Sobel 梯度粗分析，找出纹理/结构密集的候选块，给出 3~6 个建议框（如开窗、雨棚、入口），点击即套用为矩形遮罩。纯前端实现，不依赖模型。

> 排除项：引擎不提供任何视觉描述/识别端点（仅有 `img_gen`/`vid_gen`/`upscale`/`models`/`recipes`/`capabilities`/`jobs`/`model`），因此"让模型识别图片内容再返回文字"在离线单文件方案里无法实现，不做。

#### 3.4.5 掩码外保护（必做，来自既有踩坑）
引擎返回后，在浏览器内用 canvas 按遮罩二值图合成：掩码外 = 原图像素，掩码内 = 引擎结果；羽化边缘按遮罩灰度做线性混合（羽化 0 时为硬边）。同时保留引擎原始输出供比对，写入图库时 JSON 标注 `recomposed: true`。
